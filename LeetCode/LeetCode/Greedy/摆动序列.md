动态规划（Dynamic Programming, DP）是解决“摆动序列”问题最经典、最直观的方法。

### 1. 核心思路

在每一个位置 $i$，摆动序列只有两种状态：

1. **上升态 (up)**：当前元素 $nums[i]$ 大于前一个元素，形成了一个“峰”。
2. **下降态 (down)**：当前元素 $nums[i]$ 小于前一个元素，形成了一个“谷”。

我们的目标是：在遍历数组的过程中，记录以当前位置结尾的**最长上升摆动序列**和**最长下降摆动序列**的长度。

---

### 2. 定义状态

设两个动态规划数组（或变量）：

* `up[i]`：表示以前 $i$ 个元素中的某一个作为**上升结尾**的最长摆动序列长度。
* `down[i]`：表示以前 $i$ 个元素中的某一个作为**下降结尾**的最长摆动序列长度。

---

### 3. 状态转移方程

当我们遍历到第 $i$ 个元素时，比较 $nums[i]$ 和 $nums[i-1]$：

#### 情况 A：$nums[i] > nums[i-1]$

说明当前这个点可以接在之前任何一个“下降态”后面，形成一个新的“上升态”。
$$up[i] = down[i-1] + 1$$
而此时的下降态长度不变：`down[i] = down[i-1]`。

#### 情况 B：$nums[i] < nums[i-1]$

说明当前这个点可以接在之前任何一个“上升态”后面，形成一个新的“下降态”。
$$down[i] = up[i-1] + 1$$
而此时的上升态长度不变：`up[i] = up[i-1]`。

#### 情况 C：$nums[i] == nums[i-1]$

说明没有任何波动，长度保持不变：
$$up[i] = up[i-1]$$
$$down[i] = down[i-1]$$

---

### 4. 空间优化

你会发现，计算第 $i$ 位时只依赖于 $i-1$ 位。因此我们不需要整个数组，只需要两个变量 `up` 和 `down` 即可。

#### 代码实现

```cpp
class Solution {
public:
    int wiggleMaxLength(vector<int>& nums) {
        int n = nums.size();
        if (n < 2) return n;

        // 初始状态：第一个数字本身可以看作一个长度为 1 的上升序列，也可以看作下降序列
        int up = 1;
        int down = 1;

        for (int i = 1; i < n; i++) {
            if (nums[i] > nums[i - 1]) {
                // 遇到上升，更新上升态：它等于之前的下降态 + 1
                up = down + 1;
            } else if (nums[i] < nums[i - 1]) {
                // 遇到下降，更新下降态：它等于之前的上升态 + 1
                down = up + 1;
            }
            // 如果相等，up 和 down 保持不变，相当于跳过重复项
        }

        return max(up, down);
    }
};
```

---

### 5. 为什么 DP 优于你之前的代码逻辑？

1. **消除了起点依赖**：你的代码用外层循环枚举每一个 `i` 作为起点（$O(N^2)$），而 DP 自动包含了这种选择。`up` 和 `down` 在每一轮迭代中都代表了截止到目前为止能达到的最优解。
2. **处理了“平坡”**：当 `nums[i] == nums[i-1]` 时，DP 选择原地踏步，这完美解决了你之前代码中对相等元素处理模糊的问题。
3. **贪心本质的体现**：你会发现这个 DP 在更新时，实际上是在**不断更新波峰和波谷的值**。例如在连续上升段，`up` 会一直等于 `down + 1`，虽然 `up` 的数值没变，但它隐含的意思是：我们永远把当前最高点作为波峰，这样能为后面接下降段留出最大的空间。

### 总结

* **时间复杂度**：$O(N)$，只需遍历一次。
* **空间复杂度**：$O(1)$，只需两个计数变量。

这种方法比 $O(N^2)$ 的枚举要稳健得多，也避开了预处理差值带来的逻辑复杂化。
